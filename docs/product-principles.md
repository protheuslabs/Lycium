# Product Principles

Lycium exists to make the internet's free knowledge usable for building real skills and vertical understanding.

The internet already contains enormous amounts of useful educational material. The missing layer is structure: prerequisites, sequencing, practice loops, assessments, projects, source provenance, and evidence of mastery.

## Mission

Lycium turns scattered internet knowledge into complete, source-backed learning pathways for real skill development.

## Principles

### Build vertical understanding

Lycium should help learners move through a domain from foundations to applied competence:

- prerequisite concepts
- core vocabulary
- intermediate tradeoffs
- practice and feedback
- projects and portfolio evidence
- advanced connections

The product should avoid shallow tutorial hopping. A course or program is only useful if it helps the learner understand how ideas stack together.

### Prefer source-backed pathways over AI vibes

Generated courses should explain why requirements exist, which sources support them, and how they map to real curricula, certifications, or skill expectations.

AI can draft and organize, but provenance and structure are what make Lycium trustworthy.

### Use formal education structure without inheriting bureaucracy

Lycium borrows durable curriculum patterns from universities and professional programs:

- programs
- requirement groups
- prerequisites
- required vs optional material
- assessments
- capstones
- equivalencies

But Lycium should optimize for mastery, access, practical skill, and revision speed rather than seat time or institutional bureaucracy.

### Grow a public knowledge graph first

The most reusable ecosystem data should come from public or explicitly contributed educational evidence:

- source records
- source snapshots
- curriculum benchmarks
- requirement origins
- concept and prerequisite graphs
- course equivalence groups
- source quality signals
- rubrics and project requirements

This is the safest and most useful data flywheel for Lycium and the broader Protheus ecosystem.

### Keep learner data user-owned

Learner progress, goals, quiz attempts, study patterns, feedback, and career outcomes are sensitive. They should be exportable, deletable, and never silently repurposed.

Lycium's data flywheel should be a consequence of helping people learn, not a hidden extraction mechanism.

### Make source replacement normal

Sources break, age, or turn out to be weak. Lycium should treat source replacement as an expected maintenance workflow:

- stable source IDs
- snapshot hashes
- fallback source slots
- reviewable source suggestions
- course health signals

The learning path should remain stable even when individual links change.

## Product test

When evaluating a feature, ask:

Does this help someone move from scattered information to real capability?

If yes, it likely belongs. If it only adds generic AI novelty, platform sprawl, or social noise, it can wait.
